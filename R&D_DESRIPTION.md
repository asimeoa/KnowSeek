## 1. Vision

KnowSeek.ai is a fully local AI knowledge platform for industrial companies.

The system makes unorganized data (specifications, product datasheets, standards) searchable using plain language — in **German or English**. Engineers get precise answers with a direct link to the source document.

**Key principle:** Everything runs on the company's own machine. No data leaves the building.

## 2. Tech Stack — MVP

| Component | Technology | Why |
|-----------|-----------|-----|
| LLM (local) | Ollama + llama3:8b | 100% offline, runs well on Mac M1 |
| Vision / Image | LLaVA via Ollama | Image-to-text for PartSeek, fully local |
| Vector database | ChromaDB | Simple, local, no server setup needed |
| RAG framework | LangChain | Handles PDF, DOCX, Excel parsing |
| Backend API | FastAPI (Python) | REST API between AI logic and frontend |
| Frontend | React via Lovable.ai | Professional UI, generated by prompt |
| 3D Viewer | three.js + jt-js | JT files in the browser (Phase 2) |
| Container | Docker Compose | One command starts everything |
| Dev machine | Mac M1 16GB | Unified memory — Ollama runs fast |

## 3. DocSeek.ai

DocSeek lets users search all readable company documents using plain language questions. Every answer includes a **clickable source link** with the relevant text highlighted.

### 3.1 Supported File Types

| File Type | Status | Notes |
|-----------|--------|-------|
| PDF | ✅ MVP | Main format — specs, reports, standards |
| Word (.docx) | ✅ MVP | Technical documents, reports |
| Excel (.xlsx) | ✅ MVP | Requirements lists, test tables |
| Outlook (exported as PDF) | ✅ MVP | Manual export — simplest solution |
| CAD metadata (NX) | ⏳ Phase 2 | Needs special NX parser |
| .msg / .pst email archive | ⏳ Phase 2 | Uses extract-msg / python-pst library |

### 3.2 Features

| Feature | Status | Notes |
|---------|--------|-------|
| Free-text search in German + English | ✅ MVP | Ollama handles both languages natively |
| Answer with source link + highlight | ✅ MVP | Core feature — directly clickable |
| Compare across all docs (e.g. salt spray test, all OEMs) | ✅ MVP | RAG query across full vector index |
| Risk table (✅ same / ❌ different / ⚠️ conflict) | ✅ MVP | Structured output via prompt engineering |
| Query history (dropdown, reusable) | ✅ MVP | Stored in frontend |
| Generate summary + table of contents | ✅ MVP | LLM output as structured text |
| Download original document | ✅ MVP | Pulled from ChromaDB metadata |
| Team visibility: who asked this? | 💡 Nice-to-Have | Placeholder in UI — full feature in Phase 2 |
| Auto folder watcher (ingestion) | ⏳ Phase 2 | watchdog library — not needed for demo |

### 3.3 Demo Scenario

**Question:**
> "Compare all salt spray test requirements for Volvo, GM and VW across all available specification documents."

**Expected output:**
A table showing requirement, OEM, value, status (same / different / conflict), and a direct link to the source.

## 4. PartSeek.ai

PartSeek finds internal standard parts using a text description or an image upload. Results include full technical details from the part's datasheet.

### 4.1 Search Input

| Input Type | Status | Notes |
|------------|--------|-------|
| Text description (e.g. "M16 bolt stainless steel high axial load") | ✅ MVP | Semantic search via ChromaDB |
| Search by properties (material, strength, force values) | ✅ MVP | RAG searches datasheet content |
| Image upload (photo of a part) | ✅ MVP | LLaVA reads image → text → search |

### 4.2 Result Output

| Field | Status | Notes |
|-------|--------|-------|
| Part image with dimension schema (A/B/C labels) | ✅ MVP | Extracted from datasheet or stored statically |
| Material + surface treatment | ✅ MVP | Structured metadata from datasheet |
| Strength class + axial/radial force values | ✅ MVP | Technical values parsed from PDF |
| Part number + revision + drawing link | ✅ MVP | Required fields in metadata schema |
| OEM logo (VW, Volvo, GM, Stellantis, etc.) | ✅ MVP | Static logo library in frontend |
| Similar team searches visible | ✅ MVP | M16x20 vs M16x21 → shows colleague alert |
| Project usage: where is this part used? | ⏳ Phase 2 | Needs project database connection |
| Recommended torque values | ⏳ Phase 2 | Linked to NormSeek |

### 4.3 Team Collision Feature

If **Engineer A** searches for M16x20 and **Engineer B** searches for M16x21, the system shows a warning:

> *"Max Müller recently searched for a similar part. Alignment recommended."*

**Goal:** Reduce part variety, encourage standardization, avoid unnecessary new parts.

## 5. System Architecture

All components run locally inside Docker Compose. No internet needed.

```bash
docker compose up
```

| Service | Port | Function |
|---------|------|----------|
| ollama | 11434 | LLM + LLaVA vision, fully local |
| chromadb | 8000 | Vector database |
| fastapi-backend | 8001 | REST API — AI logic |
| react-frontend | 3000 | UI (built with Lovable.ai) |

### Data Flow

```
User types question
        ↓
React Frontend (Lovable)
        ↓
FastAPI Backend
        ↓
LangChain → ChromaDB (finds relevant chunks)
        ↓
Ollama (llama3) → generates answer
        ↓
Answer + source metadata → Frontend
        ↓
User sees answer + clickable source link
```

## 11. UI Design Principles

*(From the KnowSeek UI/UX Manifesto)*

- **The Infinite Book** — navigation feels like turning pages, not clicking buttons
- **Spring Physics** — all transitions have weight and momentum
- **Living Pulse** — active AI elements breathe with a slow glow
- **Module Color Bleeding** — when a module is selected, its color bleeds into borders, glows, and accents
- **Paper-Reader Layout** — dark frame with a bright document workspace in the center
- **No hard cuts** — all transitions are smooth horizontal wipes or page flips
